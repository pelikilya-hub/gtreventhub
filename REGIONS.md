# Регионы GTR Event — конвейер сбора и подключения

Как устроена мульти-региональная база и как добавлять новые регионы и
площадки, не трогая код приложения. Это спека для агентов-разведчиков
(модель подешевле) и для того, кто их запускает.

## Архитектура в двух словах

```
src/gtr/data/
  regions.json              реестр регионов: код, имена ru/en/th, центр, зум,
                            префикс id, словарь кластеров
  venues.json               историческая база Пхукета — НЕ трогаем
  regions/<code>.json       полная база региона (source of truth, с контактами)
  regions/<code>.public.json витрина без контактов — генерируется скриптом
  venue-geo.json            координаты всех площадок (общий файл)
```

- **Клиент** (`app-data.ts`) склеивает `venues.public.json` + все
  `regions/*.public.json` через `import.meta.glob` — новый регион
  подхватывается сам, код не правится.
- **Сервер** (`private-data.ts`) так же склеивает полные файлы; контакты
  и разведка в браузерный бандл не попадают никогда.
- `regionOf(venue)` — регион записи; исторические записи без поля
  `region` считаются Пхукетом.

## Добавить регион

1. В `regions.json` добавить запись: код из 3 букв, имена ru/en/th,
   `center` [lat, lon], `zoom`, `prefix` (`VEN-XXX`), `clusters` —
   закрытый словарь районов региона.
2. Создать `src/gtr/data/regions/<code>.json` с площадками (см. схему).
3. Каждой площадке дать координату в `venue-geo.json`.
4. `node scripts/validate-regions.mjs` — ошибок 0.
5. `node scripts/public-data.mjs` — сгенерирует `<code>.public.json`.
6. Готово: чипы региона появятся в «Базе» и на карте сами.

## Схема записи площадки

Обязательные строковые поля (валидатор режет пустые):
`id, name, type, tag, area, cluster, district, concept, source,
sourceType, confidence, status, notes`.

- `id` — строго `<prefix>-NNNN` (`VEN-SMU-0001`), глобально уникален.
- `tag` — только из канона приложения (`src/gtr/map-style.ts`, MAP_CATS):
  `Beach club, Nightclub, Rooftop, Bar / Lounge, Resort / MICE,
  Marina / Yacht, Show / Park, Live music, Event space, Villa, Other`.
  Свой «почти такой же» словарь недопустим: по тегу красится точка на
  карте и собираются фильтры, и несовпадение регистра роняет площадку
  в «Прочее».
- `cluster` — только из `clusters` региона в `regions.json`.
- `confidence` — `high | medium | low`.
- `source` — URL источника (официальный сайт, соцсеть, карта).
- Контакты (`phone/email/telegram`) и блок `contacts` — только в полном
  файле; в `.public.json` их вычищает генератор.

## Железные правила данных (провенанс)

- **Ничего не выдумывать.** Не нашёл факт — пустая строка, а не догадка.
- Всё неподтверждённое перечисляется в `notes`.
- `verified: false` до первого живого контакта с площадкой.
- Координата обязательна: без неё площадка не попадает на карту, и
  валидатор предупредит.

## Конвейер волны (как гнали волну A)

1. **Разведка** — параллельные Haiku-агенты, по одному на регион.
   Промпт: JSON-only, фиксированный словарь тегов и кластеров региона,
   правила провенанса выше, lat/lon обязательны. Сырьё складывается в
   scratchpad.
2. **Интеграция** — скрипт чистит сырьё, раздаёт id по порядку,
   сверяет координаты с OSM Nominatim (bbox региона, порог 2,5 км:
   расходится — побеждает OSM), пишет `regions/<code>.json` и
   `venue-geo.json`.
3. **Валидация** — `node scripts/validate-regions.mjs`, в базу пускаем
   только при нуле ошибок.
4. **Витрина** — `node scripts/public-data.mjs`.
5. **Проверка** — `npx tsc --noEmit`, `npm run build`, глазами чипы
   регионов в «Базе» и на карте.

## Скрипты конвейера

| Скрипт | Что делает |
|---|---|
| `scripts/regions-ingest.py <папка> <волна>` | принимает сырьё разведчиков: чистит, раздаёт id, отбрасывает дубли и записи без источника, сверяет координаты с OSM |
| `scripts/regions-geo.py [коды]` | догеокодирует площадки без координаты поиском по рамке региона с проверкой имени |
| `scripts/region-photos.py [коды]` | тянет главное фото с официального сайта площадки (og:image) в `rich.json` |
| `scripts/validate-regions.mjs` | ворота качества |
| `scripts/public-data.mjs` | генерация витрины без контактов |

## Известные границы

- Контуры районов (полигоны) есть только у Пхукета; в остальных
  регионах район — фильтр по кластеру, карта летит к точкам кластера.
  Полигоны тамбонов при желании нарезаются `scripts/map-districts-osm.py`.
- При росте базы за ~500 площадок публичные json регионов надо
  переводить на ленивую загрузку (сейчас клеятся жадно в бандл).
